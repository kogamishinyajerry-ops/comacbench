# 从可调用首包到航空工业仿真 Benchmark

本轮已实现的入口、首包和验收边界见 `aviation-quickstart.md` 与 `specs/aviation-plugin-v1.md`。下文是后续开发路线，**不是已实现能力清单**。工作顺序由错误能否被可靠识别决定，不按收集到的题目数量决定。

## 已完成的推进（2026-09-06，结构 v2）

`packs/aviation-structures-v2` 已实现六项结构输入检查，保留完整输入和求解证据；贡献预检加入材料契约与参考反力一致性检查，负例校准要求命中指定诊断。原有 v1 包与历史模型成绩保留。验收记录见 `report/2026-09-06-structures-v2/README.md`。

`packs/aviation-cfd-step-v1` 已打通一题 Re=100 后向台阶：OpenFOAM Foundation 10 原生网格与求解、输入/残差/守恒检查、直接壁面剪切降算、六类故障负例、统一 agent 接口和离线曲线报告。保持旧 CFDB 题及结构 v2 历史结果。验收记录见 `report/2026-09-06-cfd-step-v1/README.md`。

**三网格 × 四域组合敏感性研究已完成**：12 个 Re=100 算例在包含两次独立续跑后全部收敛；最大 fine GCI 约 0.884%，未达到预声明的 0.5% 门，细网格域差约 0.0000091%。因此不收紧原 10% 阈值、不扩展 Re=200。证据与图表见 [研究报告](../report/2026-09-06-cfd-sensitivity/README.md)。下一步在同一物理定义下追加第四档网格，并独立核验入口通量积分、梯度限制与近壁后处理；改变定义时重跑完整网格族。数值门通过后再校准容差与负例，增加独立工况和隐藏扰动。当前公开模板仍是受限基础题，不能用于通用模型排名；之后再用真实证据链建立文件级工况表与本体关联任务。

## 面向工程师的最终体验

工程师带来自己的 agent，选择“结构静力 / CFD 建模与求解 / 工程数据 / 工程知识图谱”等任务包，通过一个 wrapper 连接。先用一题确认契约，再运行锁定任务集；报告用三句话回答：完成了什么、哪里不可信、下一步应修什么。失败可定位到题意、材料、agent、工具环境、判分器中的某一层。

贡献者可以先交不完整材料。系统生成材料清单和逐项反馈，不代替用户编造几何、载荷、单位、真值或接受阈值。明确缺失的材料进入“待补齐”；仍有歧义的题面进入“待审查”。自动推导出来的候选参考答案只能作为审查材料，不直接成为金标准。

## 航空仿真主线

| 层次 | 要回答的问题 | 首选任务 | 不能冒称的结论 |
| --- | --- | --- | --- |
| 数值与程序核验 | 方程、离散化、单位和代码实现是否正确 | 解析梁、热传导、层流基础算例、网格收敛 | 不能据此说复杂飞机工况已被验证 |
| 物理验证 | 指标是否在独立数据的不确定度范围内 | 实验或高保真数据支持的翼型、分离流、结构载荷 | 不能把复现某个求解器结果等同实验验证 |
| 工作流能力 | Agent 是否正确解释要求、调用工具、诊断、修复并交付证据 | 建模→网格→求解→后处理→报告完整链 | 不能用模型自报“求解成功”证明实际执行 |
| 工程应用评估 | 指定团队、工具版本和工况下能否接受 | 内网商业求解器与团队真实任务包 | 不能从公开基础小样本推导企业接受 |

CFD 数据扩展优先从可追溯的基础验证资源开始。TMR 提供湍流模型实现核验算例、网格及网格收敛研究，并区分验证数据的用途；它本身也限制了对复杂应用的外推。NASA 官方入口当前指向迁移后的站点，新增引用应锁定新站点内容和版本。来源：[NASA 官方说明](https://www.nasa.gov/nasa-turbulence-modeling-resource/)、[TMR 当前目录](https://tmbwg.github.io/turbmodels/)。

### 下一轮：先建立 12 个工业仿真任务变体

以下是开发目标数量，不是当前覆盖数量：

| 任务族 | 正向任务变体 | 关键故障负例 | 必须保留的原始证据 |
| --- | --- | --- | --- |
| 结构静力 | 梁、支架各 2 个参数变体 | 单位错、载荷不闭合、约束错、单元类型/连接错 | 输入 deck、solver stdout、dat/sta、节点/单元清单、参考推导 |
| 模态与稳定性 | 模态、屈曲各 2 个参数变体 | 刚体模态未剔除、频率单位错、特征值选错、载荷基准错 | 特征值表、模态抽取规则、约束与载荷摘要 |
| CFD 基础 | 平板、后向台阶各 2 个工况 | 边界不全、粗网格、残差未收敛、守恒失衡、QoI 自报 | 网格检查、边界条件、残差/监控量历史、质量流量、冻结 QoI 输出 |

基础静力梁已补齐声明范围内的检查；其他结构、模态和稳定性任务仍须分别校准，再纳入上述变体。每项要求须有机器检查或明确“不覆盖”；做不到完整核验时缩小题目声明，不能通过降低难度标签或增加总分掩盖问题。

执行门按顺序记录：输入完整性 → 单位/建模 → 网格/离散化 → 求解完成 → 收敛/守恒 → 数值对账 → 扰动复算。返回每个门的 `passed / failed / not_applicable / not_checked`，总览不把 `not_checked` 涂成绿色。

本轮真实模型接口试验还提示一个后续工程任务：外部 agent 的生成时限已与制品/求解预算分开；进一步分离脚本执行与求解预算、资源隔离仍是后续项。长思考模型的截断/请求超时必须保留为协议状态。

## 企业数据与本体围绕仿真链建立

企业数据不是另建一个办公排行榜。优先评测仿真所需的材料卡、载荷表、工况表、试验观测、求解输出和技术文档之间的转换与核对。

| 能力 | 输入与交付 | 客观检查 | 材料不完整时 |
| --- | --- | --- | --- |
| 文件转换与清洗 | CSV/XLSX/Parquet → 标准工况表 | 行数守恒、精确主键、单位转换、无意损坏、缺失/重复隔离 | 列出文件/工作表/行/字段，给补齐要求 |
| 跨源关联 | 部件-材料-分析-工况-版本 | 外键完整性、版本选择、重复冲突、字段血缘 | 不猜测关联关系；输出 unresolved |
| 求解结果整编 | 原始日志/场/曲线 → 统一证据包 | 重算 QoI、文件摘要、求解器身份、时间/空间采样 | 标识缺失数据和不可计算指标，不填零替代 |
| 本体构建 | 文档与表格 → 对象、关系、证据图 | 类型/基数、引用存在性、来源片段支持、冲突处理 | 保留候选与已证实关系的区别，反馈缺少依据 |
| 图谱问答与行动 | 关系图 → 追踪查询/工程影响分析 | 标准查询答案、影响范围、证据引用、无权限数据拒绝 | 明确“不知道/无权限/材料矛盾”分别是什么 |

本体接口优先考虑标准兼容性：PROV-O 的 Entity/Activity/Agent 可以承接材料、加工/求解活动与责任主体的血缘；SHACL 已定义面向节点、路径、约束来源和严重程度的验证报告。这是后续互操作设计建议，当前 v1 仍使用轻量 JSON 及 Python 断言，**未实现 RDF/SHACL 处理器**。来源：[W3C PROV-O](https://www.w3.org/TR/prov-o/)、[W3C SHACL 验证报告](https://www.w3.org/TR/shacl/#validation-report)。

## 贡献流水线的放行条件

| 阶段 | 当前/后续 | 可验证的放行条件 |
| --- | --- | --- |
| 材料盘点 | v1 有目录/YAML预检；后续增加文档抽取 | 公开材料、判分材料、许可、版本、预期产物有明确清单 |
| 形式检查 | v1 已有规则 | 缺失/损坏/泄漏/空断言/非法权重与容差均报告字段位置；blocker=0 才能本地试跑 |
| 语义检查 | v1 只标明未覆盖与需审查；后续增加辅助检查 | 题面与参考答案、单位、工况、排序/聚合规则无未解决冲突 |
| 正负例校准 | v1 已可执行 | 参考实现全分；无产物、错误内容、邻近阈值及反事实负例均达到预期；同时保留原始结果 |
| 工程审查 | 尚未自动化 | 明确审查人、修订、结论范围和未覆盖项；机器辅助建议不得自批 |
| 隔离执行与发布 | 后续 | 文件不可越界、判分材料不对受测 agent 可读、执行可取消且限资源；发布包与签名/摘要相符 |
| 版本回归 | v1 有身份拒绝与可信续跑；后续扩展包级回归 | 新版本重新校准并与旧版区分；旧证据不覆盖；真实企业样本另设接受记录 |

## 产品化验收指标

- **工程师首次接入**：从读取指南到完成一个已许可任务，以新工程师实测时间为准；目标 15 分钟，尚未做此项用户验收。
- **可解释性**：工程师能从报告指出失败的产物、检查和修复方向；只展示总分不算通过。
- **贡献反馈**：每个阻断项包含位置、原因和修复建议；不能用“材料有问题”替代具体诊断。
- **判分可靠性**：按缺陷类型报告误放行和误拒绝，不能只报参考实现通过率；样本不足时展示计数而非虚假的统计置信度。
- **样本设计**：按几何/零部件/任务族分组，公开开发集、保留验证集、隐藏扰动集分开；不同版本和不同计算资源下的结果不直接混排。
- **可复现性**：同一身份续跑不再调用 agent；身份变化阻止复用；故障原始证据可以重放审查。
- **离线落地**：商业求解器许可与实际环境是独立检查项；Web 静态资源本地化不等于整个执行栈已通过内网验收。

近期开发顺序：**结构检查与原始证据保留 → CFD 一条完整可复算链 → 文件级企业数据及标准本体约束 → 贡献隔离与发布审查 → 工程师首次接入实测**。
