# COMACBench 内网首发审查与工程任务路线

审查日期：2026-09-21。代码基线：`5dff83c18f9782e7f4448d23899970069f0f1b87`，默认分支 `codex/trusted-resume-and-formula`。本文区分源码事实、可复现实验、建议及尚未验证事项。

## 决策

建议选择性导入，用于受控开发、工程师培训和 Agent 回归评测基础设施。完成阻断修复、目标机器验证和权属审查之前，不应作为面向全员的工程验收平台发布；不能依据现有三个产品包推导综合飞机设计能力排名。

保留现有成果的理由很充分：实际求解器执行、原生证据重算、有效性门、故障负例、版本身份与可追溯报告，比单纯回答问题的榜单更接近工程交付。但首发的核心价值应是“发现哪些交付物不能相信，并留下可复查证据”，而不是题目总量或笼统综合分。

## 首发前的 P0

### 1. 禁止结果不全或基础设施故障导致错误通过

`result_rows` 原先跳过不存在的文件，完整性没有成为 `complete` 的前提；正例结果不齐时校准可能仍通过。负例检查使用 `voided`，但公共结果协议以 `failure_mode=crash/env_mismatch` 表达不计分故障。还需检查原始结果的任务身份，不能仅按文件名覆盖为目标任务。

独立修复见 PR #1。20 项 guard 测试与 7 项真实 CLI mocked-boundary 测试通过；原版在五项回归中错误放行。未运行全仓库、真实求解器／模型或 Windows/DSH。合并后运行器身份会变更，应使用新输出目录并保留历史证据。

### 2. 离线运行闭包必须单独验证

`pyproject.toml` 只把 `comacbench` 加入 wheel，CLI 却调用 `runners` 并假设仓库资产目录存在。源码 editable install 成功不证明独立 wheel 可运行。

建议先做“受审核的源码运行发行包”，而非匆忙承诺独立 wheel：按 starter／structures／research-CFD 三种配置收集实际代码、依赖、合法资产及可分发求解器；依赖按目标 OS、CPU 架构和 Python 版本锁定，附 SHA-256、来源／许可清单和安装日志。对源码、虚拟环境、wheelhouse 和镜像分别标注用途；不能把 x86 Windows 与 ARM Linux 包混称通用离线包。

在干净目标机器断网测试：解包、检查依赖、正负例校准、参考接口运行、报告打开、受控中断与同身份恢复、变化身份拒绝恢复。缺 LFS 文件、Windows 非法文件名、缺许可证／求解器必须在开始评测前明确提示。

### 3. 受信任开发模式与不可信评测模式分开

当前本地 wrapper 进程不构成文件或网络安全隔离。公开仓库中的 `private` 目录是判分材料组织方式，不是隐藏集保密机制。这并不否定公开开发集的价值，但不应用于证明未见任务泛化。

首测仅允许经过审查的代码和合成／公开材料，最小权限运行；正式隐藏评测需独立执行账户／环境、只读公开输入、独立输出、默认禁止外联及资源限制。Gold、评分器与专家批准信息保留在评测侧。Agent 的 stdout/stderr、输出目录和报告导出均应审查敏感内容；路径散列并不能替代信息保护。

## 最值得建设的飞机设计任务族

以下是拟开发规格，不是已完成的新增 benchmark。公共版本仅使用合成或具有明确授权的材料；真实型号数据在批准的内网流程内处理。业务负责人先冻结适用范围、参考与错误边界，Agent 不修改验收规则。

### A. 工程输入表核对：最适合第一批新增任务

给定某子系统的接口尺寸表、工况表与来源清单，要求生成规范化数据、拒收记录、冲突清单和逐行血缘。保留部件号前导零；明确 mm/m、表压/绝压、版本、生效范围与坐标系。重复但相互矛盾的记录不能简单保留最后一条；输入欠缺时应请求确认，不能猜测。

判分依据为文件级内容与来源映射，不看叙述是否像报告。设置单位错、版本错、标识符丢零、假补齐和错误关联等负例；给“正确拒收、给出充分证据”的结果正向评价。最终应支持 CSV/JSON 起步，再按实际需要加入 Excel，而不是一开始追求所有企业系统接口。

### B. CFD 算例建立与审查：连接真实工程工具价值最高

从参数化弯管、进气通道或多出口缓冲腔的合成几何与工况出发。第一阶段只验几何尺度、边界命名、物性、流量／压力口径和工况覆盖，第二阶段增加真实 solver 运行、残差与质量守恒，第三阶段比较压降、总压恢复或出口流量分配的适用指标。

OpenFOAM 和 StarCCM+ 可用不同 adapter 执行，但任务的物理定义、指标定义和证据要求需要明确；不能仅因两个软件算出相近数字就宣布物理真实性。负例应含模型收敛但边界错、旧结果混入、本应确认却擅自补全、一个工况被跳过、参考截面不一致等。软件许可证失败属于环境失败，不能记为 Agent 不会 CFD。

### C. 设计更改影响与证据追踪：比继续扩充规则题更贴近协同

给定需求修订、接口对象、分析任务和证据版本，找出哪些算例／结论需要重验，形成影响清单。检查丢失的影响链、把过期分析当现行依据、跨构型误复用与无证据的“已满足”。引用必须落到具体源文件版本与位置。

### D. 仿真结果交付与复核：测完整工作，不只测生成脚本

给定多个工况结果，要求提交可复算的结果表、未通过项、适用范围和简短结论。判分程序独立从原生结果重算数值，再核对报告中的结论；关键错误不能被“报告完整、排版好”抵消。终态区分“可提交复核”“需补充证据”“分析不通过”，不授予模型设计批准权。

### E. 安装结构载荷路径与可装配性：结构线的下一步

采用合成 APU 附件支架／拉杆简化模型，给定载荷组合、安装点、包络和连接约束。先验载荷坐标、约束自由度、反力平衡及载荷传递，再考虑接触／屈曲等扩展。不能把“单梁位移正确”外推为安装设计正确，也不能只降低质量却忽略干涉、连接方式与可装配性。

## 从复现走到迁移的评测设计

每个首发工程任务族至少明确：公开练习、未参与开发的同类任务、故障／冲突输入。以几何或业务任务家族切分，避免把同一算例换几个数当作独立泛化证据。建议从约 10 个经过业务负责人复核的完整案例池建设起步，先确定哪些可供开发、哪些独立保留；这个数量是建设建议，不是已具备的 Gold 数量。

参考程序校准、脚本复现、Agent 在未见任务上成功交付应分别呈现。固定模型／工具版本、知识快照、总尝试预算和人工介入规则，再做同任务成对比较；不能把换模型、增工具、增人工和换题同时发生后的增分全归功于某个 Harness。

首版仪表盘建议直接显示分子／分母：分配任务数、有效结果数、业务通过数、危险错误漏检数、应确认但擅自继续的次数、人工介入次数和工程师复核耗时。样本少时展示逐题证据，不用大幅雷达图掩盖不确定性。基础设施作废单列，不能偷偷缩小分母让成功率上升。

## 用户体验改进 PR 的验收规格

源码审查发现，工程师页把 `p.runnable` 显示为“可以本地试跑”，实际仅代表静态材料无 blocker；首页展示研究矩阵、三能力卡片和配置说明，首次使用者仍须自行理解大量内部概念。这里是源码／流程审查，没有运行 DSH 界面、截图或完成真实用户测试。

推荐首页只给两个主动作：“体验一次评测”“评测我的 Agent”。每张任务卡先回答工作、输入、产出、依赖、证明边界；研究明细与维护者功能折叠到次级入口。状态依次为材料检查、环境检查、检查器校准、实际评测、结果复核，不能共享一个绿色标志。运行中显示正在处理的任务、阶段与预算；停止／中断保留原证据。

报告首屏先写“本次测了什么、完成几项、哪些不能相信、下一步检查什么”，再展开数值与原始产物。明确 reference fixture、历史记录、真实 Agent 三种来源；数据题的 physics 维度应给业务语义标签。正式 JSX 改动必须同步生成实际加载的 lib bundle 并做浏览器／DSH 验证，不能只改源码声称 UI 已上线。

## 公开方法依据

NASA 的 CFD V&V 教程把程序／数值验证与物理模型验证区分开，并区分简单 benchmark、子系统与完整系统层级。网格收敛、迭代收敛和守恒检查是重要组成，不能以一次残差收敛或一个简单算例通过替代工程适用性判断。

- NASA Verification Assessment: https://www.grc.nasa.gov/WWW/wind/valid/tutorial/verassess.html
- NASA Validation Assessment: https://www.grc.nasa.gov/www/wind/valid/tutorial/valassess.html
- NASA Spatial Convergence: https://www.grc.nasa.gov/www/wind/valid/tutorial/spatconv.html

本文给出的具体任务族、产品定位和优先级属于审查建议，不是 NASA 对该仓库的评估或批准。
