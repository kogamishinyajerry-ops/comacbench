# B03 清空判分与 B05 字段契约第二次修订

## 目标与边界

先独立修 B03：在 formula_cell 中将输入存在、gold 清空的位置纳入比较，
并惩罚答题范围内新增的错误内容。随后独立修 B05：明确工作簿执行交付、
括号提取与表头例外，以及 QA 的 family / clause_id / clause_no 字段范围。
不改 gold、权重、provider 参数、其他适配器或排序题 ssb_22_47 的互斥要求。
这里的 gold 指参考工作簿及答案数值。离线校准发现 oracle 脚本也遗漏清空，
因此同步修正 oracle 生成逻辑及现有 25 份脚本的清空步骤，不改其参考值列表。

## 判分口径

比较坐标为答题范围内 input 非空与 gold 非空坐标的并集，避免空白背景稀释分数。
gold 缺省值代表应清空；范围内超出并集的候选非空格作为额外错误扣分。
正确完成全部清空时允许空答题区域；gold 和 input 都没有可判内容时仍是参考契约错误。
保留既有数值容差和字符串比较口径。满分必须全部比较通过，不能由四舍五入制造满分。
新成绩通过源码摘要与有效题面摘要获得新身份，不覆盖历史结果。

## 顺序与验收

1. 现有真实 CLI + LibreOffice 测试先复现“未删行满分”，修复后不再满分。
2. 同一入口验证正确删行、部分清空、全部清空、无关位置损坏、额外写入及缺失输出。
3. B05 测试检查模型实际收到执行契约；公开题生成器与题面/哈希一致，隐藏池参考答案不变。
4. `python -m unittest discover -s tests -v` 与 `git diff --check` 退出 0。
5. 六表格 oracle、原样复制、局部完成、额外损坏负控分别产生可复查结果。
6. 冻结新协议，以相同 24 题和 seed 对 MiniMax-M3、GLM-5.3-flash 真实复跑，
   核验旧报告哈希、响应记录、同身份缓存复用和错误身份拒绝。模型得分不作为补跑条件。

若题库参考错误、身份冲突或离线负控未通过，停止依赖它的真实调用，先定位并保留证据。
