# 航空工程评测插件 v1

目标：工程师以一个本地 agent 配置调用评测包；贡献者以同一套契约提交材料，先收到逐项质量反馈，再做判分校准。航空工业仿真为主线，企业数据处理和知识本体为支撑能力。

## 本轮交付与验收

1. `python -m comacbench validate PACK`：只读预检，缺文件、摘要不符、答案泄露、无有效断言、非法容差、权重和目标不一致等以字段路径和修复建议反馈；阻断项退出 2，零 agent 调用。
2. `python -m comacbench run PACK --agent AGENT.json --out DIR`：JSON stdio 连接本地受信 agent；仅传公开题面、公开资产和输出要求；判分仍调用现有 adapter。结果、请求、回复、运行身份和 HTML 报告落盘。
3. `python -m comacbench calibrate PACK --out DIR`：显式执行参考实现及负例；结果不得充作受测模型成绩。参考实现必须全分，负例必须触发预期失败。
4. 一份自包含小包覆盖真实 CalculiX 结构求解、企业数据转换和本体关系构建。样例使用自建基础问题与虚构企业数据；不能代表飞机级设计验收或通用模型排名。
5. 原有工作台保持 GET 只读，通过插件工具和 CLI 发起操作。增加工程师入口，展示能力范围、贡献反馈和可复制命令；离线 HTML 报告可打开和筛选。
6. 负向契约测试先失败再通过；旧测试通过；真实求解与无 agent 调用的非法包试验有证据。历史报告逐文件摘要保持不变。

## 契约与边界

评测包是便携目录：`pack.yaml`、`tasks/<suite>/*.yaml`、公开材料、判分材料。任务沿用现有 TaskSpec。新增 pack 元数据记录用途、来源、许可、证据层次、检查覆盖和负例，不修改 registry 状态机。新包通过静态检查只表示可本地试跑，发布仍须校准及工程专家审查。

Agent 配置声明协议版本、名称、修订、命令 argv、超时和需要注入的环境变量名称；密钥值只留在环境。每题启动一个进程，stdin 一份 JSON，stdout 一份 JSON `{protocol, task_id, answer}`，日志写 stderr。v1 的 answer 为现有 adapter 接收的答案或制品生成脚本；直接上传已求解的商业求解器证据包是后续协议扩展，不能冒称已接入。

静态检查能发现形式矛盾和已知不合理规则，不能证明自然语言要求、工程真值和判分算法完全一致。显式未覆盖要求、参考不确定度不足、容差过宽进入“需审查”；未知执行类型拒绝通过。规则不通过不能由 LLM judge 的意见覆盖。

本地 agent 是工程师授权执行的程序；临时 cwd 与公开请求过滤不构成 OS 级保密隔离。本机开发 adapter 也不是恶意代码隔离服务。企业敏感材料及外部投稿的执行应在后续独立容器/内网执行节点完成。

## 后续路线与阶段门

| 阶段 | 具体工作 | 完成门槛 |
| --- | --- | --- |
| P0 本轮 | 评测包、stdio agent、预检、校准、可视化反馈 | 本文六条验收全部可复查 |
| P1 工业仿真可信性 | CFD/FEA 明确几何、边界、单位、网格、收敛、守恒门；保留原始求解证据；错误边界/粗网格/伪造日志负例；接入一名工程师的真实仿真 agent | 正例复算过门；每种故障有判分证据；跨 seed/工况复跑；未覆盖项显式标记 |
| P2 企业数据与本体 | 文件级 CSV/XLSX/Parquet 转换；主键/单位/版本/血缘；对象-关系-证据图、引用完整性、冲突与缺失处理 | 真正文件输入输出；污染/缺失/矛盾材料能反馈；同义图结构等价判定；保留任务族分项 |
| P3 贡献流水线 | 受控上传隔离、自动抽取材料清单、静态规则、正负例校准、专家审查、版本签名与回归 | 未审查包不能发布；许可/来源与审核可追溯；修改真值触发新版本 |
| P4 工程师插件 | DSH/MCP/CLI 一套内核；商业求解器 evidence 接口；执行节点隔离；进度与失败可视化；离线安装包 | 新工程师按指南独立接入；工具调用到报告一条链；内网实机验收 |

优先顺序：先把一条工业仿真链做可信，再扩数量。CFD 自报 QoI、分析解验证、独立求解复算、真实企业验收必须各自标注。
