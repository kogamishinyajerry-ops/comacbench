# Harness-first 评测报告（v0.3 范式转向，2026-08-24）

> 触发与定位（用户裁决）：生产环境为内网离线、可用 LLM 有限——**被测对象从「模型」
> 翻转为「harness」**。模型锁定固定对 {minimax-m3, glm-5.3}（生产可用），harness
> 臂成为唯一变量；高价值资产 = 蒸馏出的工程工作流（脚手架/反馈循环）。
> 模型间排序自本轮起不再是评测目标（v0.1/0.2 的双模型对照表转为历史档案）。

## 1. 四臂定义（harness = 受测变量）

| 臂 | 构成 | 机制 |
| --- | --- | --- |
| H0 单发 | `--iterate 1`（默认） | 裸 prompt 一问一答——v0.1 既有协议 |
| H1 反馈 | `--iterate 3` | 失败时回传 stderr/诊断，模型修订重跑（v0.2 建） |
| H2 脚手架 | `--scaffold <doc>` | 蒸馏工作流文档注入 prompt 前部（本轮新建） |
| H3 脚手架+反馈 | `--iterate 3 --scaffold` | 生产形态组合（本轮新建） |

评分语义全部不变（score 只由判分管线决定）；增益 = 臂间均分差。

## 4. 读数（harness 价值的四条实证结论）

1. **蒸馏工作流是「不可为→可为」的开关**：M3+pycycle 从 0/10 到 **10/10 满分**
   ——模型没变，变的只有注入的 API 组装知识。这直接量化了「价值在 harness」：
   对语料外工程域，一份 150 行的蒸馏文档 = 模型能力的 0→1。
2. **模型×harness 存在交互，工作流要配模型**：M3 严格遵循脚手架（H2 即满，H3 无
   增量）；glm-5.3 会改写脚手架引入偏差（H2 仅 0.3），但反馈循环能修复其偏差
   （H3 回到 0.9）——**不同模型需要不同臂组合**，生产 harness 应按模型配臂。
3. **脚手架对 foam 是部分解**（M3 0.36-0.40）：结构层知识（算例骨架）被吸收，
   但物理正确性（NMSE）仍靠模型——工作流能解决的与不能解决的边界清晰可见。
4. **glm-5.3 的 provider 事实（工程坑，已修入 providers）**：难题上无视
   `thinking:disabled`（reasoning 耗尽 max_tokens，content 空）；H0 无脚手架时
   思考无界致整批中断（本轮用 --resume 自愈循环收满，每题多次重试）。
   **无脚手架的前沿思考模型在 pycycle 上连错误代码都产不出**——H2/H3 不只是
   提分，是让它能入场。
